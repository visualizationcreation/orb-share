A GitHub account is needed to submit. Your ORB stays in your own repository.

01 / CREATE

Start with a question.

Choose a topic, an audience and something worth understanding. Use the ORB basic prompt in your AI chat, or invoke your installed ORB skill. Then explore, refine and verify the material.

TRY A STARTING POINT

“Create an ORB about urban trees for a curious beginner. How do trees change the experience of a city?”

New to the method? Open The ORB Skill field guide. Typing /orb in a tool does not install the skill; use the public prompt when it is unavailable.

02 / BUILD

Turn the exploration into a webpage.

Ask your AI to create an ORB Web artifact with index.html as its entry file. Use this brief after exploring your chosen topic.

Review the result: test compass moves, sources, home, mobile layout and every available media control. Remove private notes and use assets you have permission to share.

What about narration and video?

Reading-only ORBs are welcome. An Active Journey or Rest Journey can be authored from the completed ORB. A script is separate from recorded narration or a finished film. Choose the mode before producing a video, and add media to your listing only when it is published and plays correctly.

03 / PUBLISH

Give your ORB a public home.

  1. On GitHub, create a repository. Pick a topic name, choose Public and add a README.
  2. Use Add file → Upload files. Put index.html at the root, along with its assets in the paths it expects. Commit the files. Add a blank .nojekyll file for a plain static site.
  3. Open Settings → Pages. Choose Deploy from a branch → main → / (root) and save.
  4. Wait for deployment and open the live URL shown by GitHub. Test that published page, including mobile layout and media.
  5. Open your repository’s deployed commit and select Copy full SHA. This identifies the version you are submitting.

For example, a repository named urban-trees-orb usually publishes at https://YOUR-USERNAME.github.io/urban-trees-orb/. Use the actual URL shown by Pages. GitHub’s Pages guide ↗

05 / SUBMIT

Send a pull request.

A pull request is a proposed change for the owner to review. You can do this entirely on GitHub.

  1. Open the ORB Share repository and select Fork → Create fork. Already have a fork? Select Sync fork first.
  2. In your fork, open orbs.json and use the pencil to edit it. Insert your generated object into the orbs array. Keep existing listings. If it is empty, replace [] with brackets containing your object.
  3. Commit on a new branch, such as add-my-orb. Keep your PR limited to your listing.
  4. Select Contribute → Open pull request. The base must be visualizationcreation/orb-share, branch main; the head is your fork’s submission branch.
  5. Title it Add ORB: Your title, complete the checklist and create the pull request.

06 / OWNER REVIEW

Approved, then featured.

@visualizationcreation reviews your live ORB, sources, usability, media rights and submitted version. If changes are requested, update the same branch and reply in the pull request.

SubmittedOwner reviewsApproved & mergedFeatured in the archive

After the owner approves and merges, GitHub Pages publishes the listing and it appears in the main page’s Community ORBs section. Open or unmerged submissions do not appear there.

Your site stays under your control. The listing links to the reviewed source revision. Submit material updates through another PR. Acceptance and review time are at the owner’s discretion.
